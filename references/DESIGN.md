# Справочник оформления

Оформление задают `assets/runtime/review-template.html` и `build-review.py`.
Они являются источником точных значений CSS.
Меняй их только при обновлении навыка, а не для отдельного отчета.
Контракт содержания находится в [SPEC.md](SPEC.md).

## Структура страницы

1. Шапка с названием, путем модуля и диапазоном SHA.
2. Оглавление со ссылками на методы.
3. Отдельный лист каждого метода.
4. Заголовок метода с состоянием и ссылкой на оглавление.
5. Тезис и блоки `summary`.
6. Фрагменты с пояснением над кодом.

Измененный метод показывает две колонки: старый и новый код.
Внутри изменения каждая колонка идет своим потоком.
Добавленный или удаленный метод показывает одну колонку.

## Визуальные признаки

- Страница серая. Листы методов белые.
- Панель кода светло-серая. Дополнительные блоки бежевые.
- Добавленные строки отмечены зеленым. Удаленные строки отмечены красным.
- У целиком добавленного или удаленного метода нет цветной полосы.
- Заголовок метода остается сверху при прокрутке.
- Пояснение содержит ссылку на фрагмент.
- Сворачиваемый код находится в `details`.
- Шрифты системные. Внешние ресурсы не загружаются.
- Темная тема не предусмотрена.

## Проверка в браузере

Проверь страницу на ширине 1440 px:

- У страницы нет горизонтальной прокрутки.
- Схемы помещаются в панели. Узлы не перекрываются.
- Блок `summary` не повторяет пояснение фрагмента.
- Длинные запросы свернуты.
- Ссылки пояснений ведут к нужным фрагментам.

Мобильный вид не входит в текущий дизайн.

## Автоматическая проверка

`check-review.py` проверяет:

- совпадение CSS с шаблоном;
- отсутствие дополнительных стилей и внешних ресурсов;
- единственный штатный скрипт печати;
- соответствие оглавления листам методов;
- наличие состояния метода, тезиса и ссылки на оглавление;
- наличие пояснений и выделенной первой фразы;
- лимит размера страницы.

Эта проверка не заменяет просмотр в браузере.
