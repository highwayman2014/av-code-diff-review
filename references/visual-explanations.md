# Выбор визуализации

Выбирай минимальный вид, который раскрывает изменение.

| Что нужно объяснить | Блок |
|---|---|
| Порядок шагов | `flow` |
| Условие или алгоритм | `pseudo` |
| Несколько источников, развилка, слияние | `diagram` |
| Соответствие условия и результата | `table` |
| Ответственность методов | `pseudo` с отступами и `label: "вызовы"` |
| Простая правка строк | Только diff и пояснение |

Используй реальные имена.
Не повторяй одну мысль в схеме, псевдокоде и абзаце.
Формат полей и положение блоков заданы в [SPEC.md](SPEC.md).

## Псевдокод

Сохраняй существенные условия, порядок и ранний выход.
Убирай технические детали.
Обычно достаточно 5–10 строк.
Псевдокод не является исполняемым BSL.

## Схема

Сборщик создает inline SVG из `diagram.edges`.
Используй короткие подписи узлов: до 25 символов.
Ребро должно отражать передачу данных или порядок управления.
Зависимость временных таблиц не означает последовательность выполнения.

Используй схему без циклов.
Сборщик размещает выходы в последней колонке по алфавиту.
Если порядок выходов важен, добавь к подписям номера.

Пример:

```json
{
  "type": "diagram",
  "place": "summary",
  "edges": [
    ["Источник А", "Сопоставление"],
    ["Источник Б", "Сопоставление"],
    ["Сопоставление", "Расчет"]
  ],
  "mark": {"Источник Б": "new"}
}
```

Если схема не передает существенный смысл, используй таблицу или псевдокод.
Если штатных блоков недостаточно, сообщи об ограничении формата.
