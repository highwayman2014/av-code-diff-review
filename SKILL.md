# Объяснение изменений кода

Агент пишет содержание в JSON. Сборщик получает код из Git и задает оформление.

## Порядок работы

1. Примени инструкции проекта. Получи постановку, согласованные решения и границы отчета. Создание отчета не требует изменения исходников, веток или баз.
2. Определи репозиторий и диапазон. Если диапазон не задан, используй `git merge-base main HEAD` и `HEAD`. Сохрани полные SHA в `base` и `head`.
3. Получи список файлов через `git diff --name-only <base> <head>`. Изучи измененные методы и нужные вызовы в обеих ревизиях. Учитывай расширения по правилам проекта.
4. Прочитай [контракт спецификации](references/SPEC.md). Если нужны дополнительные блоки, прочитай [выбор визуализации](references/visual-explanations.md).
5. Запиши спецификацию в разрешенный каталог артефактов. Расположи методы от точки входа к деталям. Сверь список методов со всем заявленным диапазоном. Явно укажи пропуски.
6. Собери отчет:

   ```text
   python -I <skill>/scripts/render-review.py <spec.json> --out <review.html>
   ```

   Передай абсолютные пути. Требования к среде указаны в [README](README.md#требования).
7. Если сборка завершилась с ошибкой, исправь спецификацию. Если формат не позволяет выразить нужное, сообщи об ограничении. Меняй только спецификацию, а не HTML или runtime.
8. Если доступен разрешенный просмотр, проверь страницу на ширине 1440 px по [визуальному чек-листу](references/DESIGN.md#проверка-в-браузере). Иначе укажи, что визуальная проверка не выполнена.
9. Верни ссылку на HTML, результат проверки, диапазон SHA и границы охвата.

Сборщик сам запускает проверку оформления. Для отдельной повторной проверки используй:

```text
python -I <skill>/assets/runtime/check-review.py <review.html>
```

Проверка оформления не подтверждает смысловую точность пояснений или выполнение кода в 1С.

## Изменение навыка

При изменении оформления прочитай [DESIGN.md](references/DESIGN.md).
После обновления или переноса выполни:

```text
python -I <skill>/scripts/test-review.py
```
