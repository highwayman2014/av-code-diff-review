# av-code-diff-review

Навык создает переносимый HTML-отчет по изменениям BSL в Git.
Отчет показывает код до и после изменения.
Агент добавляет пояснения, псевдокод и схемы.

Это инструмент объяснения diff.
Он не заменяет поиск дефектов, проверку требований или тесты в 1С.

## Требования

- Python 3.10 или новее. Команда `python` должна запускать эту версию.
- Git в `PATH`.
- Локальный Git-репозиторий с BSL-модулями в UTF-8.

Сторонние пакеты Python не нужны.
Платформа 1С и MCP-серверы не нужны.
Скрипты сборки не используют сеть.

### История Git

Сохрани изменения в коммитах.
В локальном репозитории должны быть доступны состояния до и после изменения.
Незакоммиченные изменения в отчет не входят.

Укажи два коммита для сравнения.
Без явного диапазона навык использует `git merge-base main HEAD` и `HEAD`.
Для этого нужны локальная ветка `main` и история до общего предка.

Агенту нужны постановка и согласованные решения, если отчет должен объяснять цель изменения.
Для отчета только по коду явно укажи это ограничение.

## Установка

### Через skills CLI

Для этого способа нужен Node.js 22.20 или новее с командой `npx`.
Node.js нужен только установщику. Сборка отчета использует Python и Git.

Для установки в текущий проект выполни команду из его каталога:

```bash
npx skills add highwayman2014/av-code-diff-review --skill av-code-diff-review
```

Выбери агента в диалоге установщика.

Для установки на уровне пользователя добавь `-g`:

```bash
npx skills add highwayman2014/av-code-diff-review --skill av-code-diff-review -g
```

Для просмотра доступных навыков без установки выполни:

```bash
npx skills add highwayman2014/av-code-diff-review --list
```

Установщик загружает файлы из GitHub. Для этого нужен доступ к сети.
Подробнее см. в [документации skills CLI](https://github.com/vercel-labs/skills).

### Через Git

Если skills CLI не подходит, склонируй репозиторий в каталог навыков своего агента:

```bash
git clone https://github.com/highwayman2014/av-code-diff-review.git <skills-dir>/av-code-diff-review
```

Замени `<skills-dir>` на каталог навыков приложения.
Не вкладывай навык в другой каталог с тем же именем.

### Проверка установки

Если приложение не обнаруживает навыки, передай агенту путь к `SKILL.md`.
Если приложение загружает список навыков при запуске, перезапусти его.

Проверь установку:

```bash
python --version
git --version
python -I <skill>/scripts/test-review.py
```

Здесь и далее `<skill>` означает абсолютный путь к каталогу навыка.
Замени значения в угловых скобках перед запуском команды.
Пути с пробелами заключай в кавычки.

Тест создает временный Git-репозиторий.
Он не меняет рабочий репозиторий.
Тест проверяет переносимость, несколько модулей, добавление и удаление методов.
Он также проверяет неверный якорь, защиту от перезаписи и отказ при изменении CSS.

## Пример запроса агенту

```text
Используй av-code-diff-review.
Создай HTML-разбор изменений в репозитории /work/service.
Сравни коммиты <полный-base-SHA> и <полный-head-SHA>.
Объясни все измененные BSL-методы.
Постановка находится в /work/tasks/EXAMPLE/description.md.
Запиши спецификации в /work/review/specs.
Запиши HTML в /work/review/output.
Исходники не меняй.
Если нужны несколько страниц, укажи охват каждой части.
```

В спецификации агент сохраняет полные SHA.
Правила выбора диапазона указаны в разделе [«История Git»](#история-git).

## Пример спецификации

Сохрани JSON вне каталога установленного навыка.
В примере функция `ПолучитьЛимит` находится в начале указанного модуля.
Между коммитами она меняет возвращаемое значение с 10 на 20.
Это условный пример, а не готовая спецификация для любого репозитория.

```json
{
  "task": "EXAMPLE",
  "repo": "/work/service",
  "base": "<полный-base-SHA>",
  "head": "<полный-head-SHA>",
  "file": "src/cf/CommonModules/Лимиты/Ext/Module.bsl",
  "methods": [
    {
      "id": "get-limit",
      "method": "ПолучитьЛимит",
      "lead": "Лимит увеличен до 20.",
      "hunks": [
        {
          "at": 1,
          "blocks": [
            "Лимит увеличен с 10 до 20. Вызовы функции получают новое значение."
          ]
        }
      ]
    }
  ]
}
```

Замени путь, SHA, имя метода и номер строки на значения своего репозитория.
Полный формат и правила содержания заданы в [references/SPEC.md](references/SPEC.md).

Собери отчет:

```bash
python -I <skill>/scripts/render-review.py /work/review/specs/EXAMPLE.json --out /work/review/output/review-EXAMPLE.html
```

Если результат уже существует, выбери другое имя.
Для намеренной замены добавь `--overwrite`.

Обертка сама проверяет HTML.
Она публикует результат только после успешной сборки и проверки.
При ошибке проверки прежний результат сохраняется.
Исходный JSON не изменяется.

Открой результат в браузере.
Проверь его по [визуальному чек-листу](references/DESIGN.md#проверка-в-браузере).

## Ограничения

- Поддерживаются методы BSL. Другие языки и XML не поддерживаются.
- Объявления методов должны соответствовать текущему поиску. Подробности указаны в контракте спецификации.
- Изменения вне методов не входят в отчет.
- Переименованный метод может потребовать двух записей: удаление старого и добавление нового.
- Одна спецификация относится к одному репозиторию. Модулей может быть несколько.
- Лимит HTML-страницы составляет 200 000 байт.
- Сворачивание кода не уменьшает размер HTML. Большой отчет нужно разделить.
- Проверка оформления не обнаруживает пропущенные методы. Агент сверяет охват отдельно.
- Мобильный вид не входит в текущий дизайн.
- Внешние ресурсы не нужны. Результат можно открыть без сети.

## Безопасность

Спецификация содержит локальный путь к репозиторию.
HTML содержит код из выбранных коммитов, в том числе внутри свернутых блоков.
Проверь оба файла перед передачей другим людям.
Не включай секреты, подключения и корпоративные данные в публичные примеры.

Сборка не выполняет BSL-код.
Она не загружает изменения в 1С и не меняет ветки Git.
Для просмотра и публикации отчета соблюдай правила своего проекта.
